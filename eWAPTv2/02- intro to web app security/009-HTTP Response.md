
HTTP responses are the messages sent by a web server back to a client (such as a browser) after receiving and processing an HTTP request. These responses include status codes, headers, and optionally a body that carries the actual content or error message.

A complete HTTP response is typically structured into three parts:

1. **Status Line**
2. **Response Headers**
3. **Optional Response Body**

## 1. Common HTTP Status Codes 

Status codes are 3-digit numbers included in the status line of a response to indicate the outcome of the request. These codes are divided into five major categories:

| Code | Category     | Meaning               | Description                                                                                                                                                |
| ---- | ------------ | --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 200  | Success      | OK                    | The request succeeded, and the server has returned the requested data. This is the most common status for successful GET requests.                         |
| 301  | Redirection  | Moved Permanently     | The requested resource has permanently moved to a new location. The new URL should be used for all future requests. Useful for SEO and site restructuring. |
| 302  | Redirection  | Found                 | The resource is temporarily located at a different URL. Used during temporary redirections, but modern apps often prefer 303 or 307 for clarity.           |
| 400  | Client Error | Bad Request           | The server cannot process the request due to client-side issues like malformed syntax or missing parameters.                                               |
| 401  | Client Error | Unauthorized          | The client must provide valid credentials. Often appears when accessing protected resources without authentication.                                        |
| 403  | Client Error | Forbidden             | The client is authenticated but does not have permission to access the resource. Used for role-based access control.                                       |
| 404  | Client Error | Not Found             | The server could not locate the requested resource. Very common when links are broken or the URL is incorrect.                                             |
| 500  | Server Error | Internal Server Error | A generic server error occurred. Often caused by bugs or misconfigurations on the server.                                                                  |

## 2. HTTP Response Headers

Headers in the HTTP response provide metadata and instructions that guide how the client should process the returned content.

### Date Header

* **Purpose**: Shows the timestamp when the response was generated by the server.
* **Usage**: Important for time-based validation, logging, and caching.

**Example:**

```
Date: Fri, 13 Mar 2015 11:26:05 GMT
```

---

### Cache-Control Header

* **Purpose**: Controls how responses are cached by browsers and intermediate proxies.
* **Usage**: Enhances web app performance, limits stale data, and enforces privacy.

**Example:**

```
Cache-Control: private, max-age=0
```

#### Cache-Control Directives:

| Directive           | Description                                                                                                       |
| ------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `public`            | Response can be cached by any cache including proxies. Suitable for shared/static resources.                      |
| `private`           | Response is user-specific and should not be cached by shared proxies.                                             |
| `no-cache`          | Client must revalidate with server before using the cached copy. Doesn't block caching but requires confirmation. |
| `no-store`          | Fully disables caching. Response is not stored anywhere. Useful for sensitive data (e.g., banking).               |
| `max-age=<seconds>` | Defines how long (in seconds) the content can remain fresh before revalidation.                                   |

---

### Content-Type Header

* **Purpose**: Specifies the MIME type of the response body.
* **Usage**: Helps the client determine how to parse and render the content.

**Example:**

```
Content-Type: text/html; charset=UTF-8
```

Common MIME types:

* `text/html`: HTML content
* `application/json`: JSON data (used in APIs)
* `text/plain`: Raw text
* `image/png`: PNG image
* `application/xml`: XML data

---

### Content-Encoding Header

* **Purpose**: Indicates how the response body is compressed.
* **Usage**: Saves bandwidth and speeds up loading time for large responses.

**Example:**

```
Content-Encoding: gzip
```

Common values:

* `gzip`: Widely used compression method
* `deflate`: Another common compression format

If the client does not support the specified encoding, it may fail to interpret the content properly.

---

### Server Header

* **Purpose**: Identifies the server software handling the request.
* **Usage**: Helps with diagnostics, but can expose server fingerprinting info to attackers.

**Example:**

```
Server: gws
```

"gws" stands for Google Web Server, used internally by Google services.

---

### Content-Length Header

* **Purpose**: Indicates the size of the response body in bytes.
* **Usage**: Helps the client determine when the full response has been received.

**Example:**

```
Content-Length: 258
```

In streaming or chunked responses, this header may be omitted, and transfer ends when the server closes the connection or uses chunked transfer encoding.

---

## 3. Full HTTP Response Example

```
HTTP/1.1 200 OK
Date: Fri, 13 Mar 2015 11:26:05 GMT
Cache-Control: private, max-age=0
Content-Type: text/html; charset=UTF-8
Content-Encoding: gzip
Server: gws
Content-Length: 258

<PAGE CONTENT>
```

This example includes:

* A **status line** with `200 OK`
* Multiple headers (Date, Cache-Control, etc.)
* A compressed body (`Content-Encoding: gzip`)
