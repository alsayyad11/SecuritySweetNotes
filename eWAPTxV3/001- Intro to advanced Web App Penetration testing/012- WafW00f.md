
## What is WafW00f?

**WafW00f** is a Python-based tool used to **detect and identify Web Application Firewalls (WAFs)** protecting a web application.

A **WAF** is a security layer that filters, monitors, and blocks malicious HTTP traffic to a web application. Detecting a WAF is an important step in penetration testing because it helps you:

* Understand **security defenses** protecting the target.
* Adjust your **attack strategy** (payloads, rate, techniques).
* Avoid unnecessary detection or triggering WAF protections prematurely.

WafW00f does not exploit vulnerabilities—it only **identifies WAFs** and provides information about their type and presence.

---

## Key Features

* Detects over **100 different WAFs**, including **ModSecurity, Cloudflare, AWS WAF, F5 BIG-IP, Incapsula, Sucuri**, and more.
* Works by **sending crafted HTTP requests** to the target and analyzing responses.
* Lightweight, fast, and compatible with **Python 3**.
* Can be integrated into automated reconnaissance pipelines.
* Provides **clear output**: detected WAF, method of detection, and confidence level.

---

## How WafW00f Works

1. WafW00f sends **HTTP requests with specific signatures** (special headers, parameters, or payloads) to test if the responses differ from normal requests.
2. Analyzes the **response behavior**, headers, cookies, and body content.
3. Compares results with its **database of known WAF fingerprints**.
4. Reports whether a WAF is detected and, if so, which type it is.

It uses **passive detection first**, which is safe and non-intrusive, but can use **active detection** if you enable specific tests.

## Installation

### 1) Install via pip (recommended)

```bash
pip3 install wafw00f
```

Check version:

```bash
wafw00f --version
```

### 2) Clone from GitHub (manual method)

```bash
git clone https://github.com/EnableSecurity/wafw00f.git
cd wafw00f
sudo python3 setup.py install
```

### 3) Docker (optional)

```bash
docker pull enablesecurity/wafw00f
docker run -it enablesecurity/wafw00f wafw00f http://example.com
```

## Basic Usage

### Detect WAF for a single website

```bash
wafw00f http://example.com
```

**Output example:**

```
Checking http://example.com
[+] The site is behind a Cloudflare WAF
```

### Verbose mode (more details)

```bash
wafw00f -v http://example.com
```

Output shows:

* HTTP request sent
* WAF detection rules triggered
* WAF type
* Confidence

### Scan multiple sites

Create `targets.txt`:

```
http://example.com
http://testsite.local
```

Then run:

```bash
wafw00f -f targets.txt
```

### Active detection (more aggressive)

```bash
wafw00f --active http://example.com
```

**Note:** Active mode sends more intrusive payloads, may trigger WAF logging.

### Detect WAF via proxy (e.g., Burp)

```bash
wafw00f --proxy http://127.0.0.1:8080 http://example.com
```

Useful if you want to inspect WafW00f requests via Burp Suite or ZAP.

## Output Interpretation

WafW00f output includes:

* **Target URL**
* **WAF detected** (name and type)
* **Confidence** (how sure the detection is)
* Optional details on **headers, cookies, or response patterns** used for detection.

**Example:**

```
Checking http://example.com
[+] The site is behind a Cloudflare WAF
[+] WAF detection confidence: High
[+] Detection method: Cookie and header analysis
```

Interpretation:

* High confidence → WAF likely present
* Low confidence → WAF may exist but uncertain, consider additional testing

## Integration in Pentesting Workflow

WafW00f is usually run **after reconnaissance** and **before exploitation**, as it helps:

1. Identify **WAF presence** and type.
2. Adjust payloads:

   * Some WAFs block common SQLi or XSS payloads.
   * Some WAFs allow URL-encoded or obfuscated payloads.
3. Plan bypass strategies:

   * Change User-Agent, headers, request encoding
   * Try alternative injection techniques
4. Document WAF protection in **pentest report**.

## Automation Example

**Recon + WAF detection pipeline:**

```bash
# Step 1: Discover live hosts with nmap
nmap -p80,443 10.10.10.0/24 -oG livehosts.gnmap
awk '/Up/ {print $2}' livehosts.gnmap > livehosts.txt

# Step 2: Detect WAFs for all hosts
wafw00f -f livehosts.txt > waf_report.txt

# Step 3: Filter results for WAFs detected
grep "\[+\] The site is behind" waf_report.txt > detected_wafs.txt
```

## Limitations

* **False negatives**: WAF may be present but stealthy, not triggering WafW00f rules.
* **False positives**: Some generic rules may mistake normal headers for a WAF.
* **Encrypted traffic**: Must handle HTTPS correctly; self-signed certs may need `--no-verify`.
* **Advanced WAFs**: Some cloud WAFs (AWS, Azure Front Door) may bypass WafW00f detection without active payloads.
