# HackerOne - Arbitrary File Upload and Stored XSS via Malicious SVG in Support Request

[Original Report](https://hackerone.com/reports/865354)

---

## Overview: What Happened?

A vulnerability in a **support request file upload form** used by the **U.S. Department of Defense (DoD)** allowed an attacker to upload **arbitrary file types**, including **malicious SVG files**. These files could trigger **Stored Cross-Site Scripting (XSS)** in the browser of the support staff reviewing the submissions.

The server failed to validate:

* The **file extension** of uploaded files
* The **MIME type** of the uploaded files
* The **actual content** of the files

This allowed an attacker to disguise a malicious SVG or HTML file using a trusted extension (like `.svg`, `.xls`, or `.docx`) and deliver a payload to the support agent.

---

## Methodology: Step-by-Step Attack Path

### 1. Accessing the Support Request Form

* The attacker created an account on the target DoD platform.
* Navigated to a form under **Faculty/Staff IT Support** (or similar categories).

---

### 2. Uploading Malicious File

* The attacker completed the support request form and uploaded a malicious file (e.g., `.svg` containing JavaScript).
* The form accepted the upload without validating the file type.
* The support ticket was submitted, and the uploaded file became accessible for support staff.

---

### 3. Triggering the XSS

* If a support agent opened the file directly in the browser (e.g., an SVG rendered inline), the embedded JavaScript executed.
* Example payload:

```xml
<svg xmlns="http://www.w3.org/2000/svg" onload="alert('XSS')" />
```

* Instead of `alert()`, the attacker could use `window.location` to redirect to a phishing page mimicking a DoD login portal.

---

## Technical Explanation

The vulnerability existed due to:

* Lack of **whitelisting** of acceptable file types (e.g., only `.pdf`, `.jpg`, etc.)
* No **server-side validation** of file MIME types or content
* Files were directly accessible for viewing, and browsers rendered SVGs natively
* No use of protective headers like `Content-Disposition: attachment` or proper CSP

---

## Impact

* **Stored XSS** targeting DoD support agents
* **JavaScript execution** in privileged internal environments
* Potential for:

  * **Phishing attacks**
  * **Credential theft**
  * **Session hijacking**
  * **Browser-based exploitation**

If the uploaded file was an executable (e.g., `.exe`) and a user downloaded and opened it, it could even result in **Remote Code Execution (RCE)**, although less likely.

---

## Variants and Extended Scenarios

| Scenario                         | Description                                                          |
| -------------------------------- | -------------------------------------------------------------------- |
| **SVG with Embedded JavaScript** | Inline `<svg>` element triggering script execution                   |
| **HTML disguised as DOC/XLS**    | Uploading `.html` file renamed to `.doc` or `.xls`                   |
| **Executable disguised**         | Uploading `.exe` file with `.pdf` extension                          |
| **Cross-form exposure**          | Vulnerability present in other support forms on the same platform    |
| **Blind XSS hits**               | Logging beacon hits via payloads (e.g., Slackbot-triggered webhooks) |

---

## Checklist

Use this checklist to test for similar file upload vulnerabilities:

| Step                             | Description                                                         | Status |
| -------------------------------- | ------------------------------------------------------------------- | ------ |
| **Upload Feature Found**         | Locate file upload in a support or contact form                     | 🔲     |
| **Try Malicious File**           | Upload file with HTML or SVG + JavaScript content                   | 🔲     |
| **Check Frontend Restrictions**  | Observe whether UI blocks certain file types                        | 🔲     |
| **Bypass via Extension Change**  | Rename `.html` or `.svg` to `.docx` / `.xls` / `.txt`               | 🔲     |
| **Intercept Request**            | Modify MIME type to `text/html` or `image/svg+xml` in Burp Suite    | 🔲     |
| **Confirm File Storage**         | Ensure file is stored and accessible to internal users              | 🔲     |
| **Trigger JavaScript Execution** | Open the file in browser and check if JS executes                   | 🔲     |
| **Monitor for Blind XSS**        | Check logs or webhooks for triggered payloads (e.g., Slackbot hits) | 🔲     |
| **Test Other Forms**             | See if same issue exists in other service catalog forms             | 🔲     |
| **Check Headers on Access**      | Look for `Content-Disposition`, MIME-type, and CSP protection       | 🔲     |
