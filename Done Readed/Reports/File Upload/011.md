# Private Program - RCE via Race Condition on Temporary Local File Before S3 Upload

[Original Write-Up](https://infosecwriteups.com/race-condition-that-could-result-to-rce-a-story-with-an-app-that-temporary-stored-an-uploaded-9a4065368ba3)

---

## Overview: What Happened?

A **race condition vulnerability** was discovered in a private bug bounty program where an application **temporarily stored uploaded files on its local server for \~2 seconds** before moving them to **Amazon S3**.

By exploiting this time window, an attacker could:

* Upload a malicious `.php` reverse shell using an unprotected upload endpoint.
* Access the local path **before** the file was moved to S3.
* Trigger **Remote Code Execution (RCE)** on the app’s server.

---

## Methodology: Step-by-Step Attack Path

### 1. Internal Dashboard Access

* Attacker gained access to an internal admin dashboard using dumped credentials from a prior **SQL Injection**.
* Located a **file upload feature** used to publish articles via `upload.php`.

---

### 2. Initial Upload Attempt

* Tried uploading `.php` shell via `upload.php`.
  → Blocked due to **extension filtering**.
* Tried bypassing using:

  * Upper/lower case: `.PhP`
  * Alternate extensions: `.php3`
  * Tricks: null byte, double extension, etc.
    → All failed.

---

### 3. Discovered Alternative Upload Function: `modify.php`

* Found an “Edit” button that allowed modifying existing files.
* The upload form for edits used a different backend: `modify.php`.
* This function **did not filter any file types**.
* Uploaded a **`reverse.php` shell** successfully.

---

### 4. Problem: Files Moved to Amazon S3

* Despite successful upload, the server **moved files to S3**, preventing execution of the `.php` shell.
* Accessing the shell on S3 returned **403 or Not Executable** errors.

---

### 5. Exploiting the Race Condition

* Sent **multiple upload requests quickly (race condition)** using Burp Suite Intruder.
* After several tries, received an **error response revealing the local storage path** before the file was moved.

Example error response (with local path):

```
/var/www/html/uploads/temp/12345_reverse.php
```

---

### 6. Triggering the Shell

* Set up a **reverse shell listener**:
  `nc -lvp 4444`
* Repeated the race condition by re-uploading the shell with `modify.php`.
* Simultaneously sent multiple requests to the revealed **local file path** in browser.
* Eventually, caught a shell when the file was still on disk before moving to S3.

---

## Technical Explanation

The vulnerability existed because:

* Uploaded files were **temporarily stored locally** before being transferred to S3.
* There was a **short window (\~2 seconds)** where the file was executable on the local server.
* No access control or temporary file isolation was applied during this window.
* `modify.php` endpoint **did not validate file type**, unlike `upload.php`.

### What is Amazon S3?

**Amazon S3 (Simple Storage Service)** is a cloud-based object storage system provided by AWS. It’s often used to store uploaded files, media assets, and backups.

Key features relevant to this case:

* **Files are not executed on S3** (no support for dynamic code like `.php`)
* Files are accessed via **unique public or signed URLs**
* Once the file is moved to S3, **any embedded shell becomes useless** unless it was accessed during the local phase

That’s why the attacker had to exploit the small delay **before** the file was moved to S3 — it was the only time the malicious script could actually be executed on a server that supports PHP.

---

## Impact

* **Remote Code Execution (RCE)** on the internal application server.
* If the server had high privileges, attacker could:

  * Execute system commands
  * Access internal resources
  * Move laterally or escalate privileges
* Possibility to exfiltrate sensitive internal data or persist backdoor access.

## Variants and Extended Scenarios

| Scenario                      | Description                                                                |
| ----------------------------- | -------------------------------------------------------------------------- |
| **Race Condition Timing**     | Exploiting a short window (1–2 seconds) before file transfer to S3         |
| **Unfiltered Upload Point**   | Bypassed restrictions using `modify.php` which lacked file validation      |
| **Path Disclosure via Error** | Error messages revealed exact local storage path of uploaded shell         |
| **Double Upload Trick**       | Uploading malicious file repeatedly to increase chance of hitting race win |
| **S3 Transfer Delay**         | Leveraging backend delay to trigger shell before S3 sync                   |

## Checklist

Use this checklist when testing for similar upload-based RCE via Race Condition:

| Step                              | Description                                                      | Status |
| --------------------------------- | ---------------------------------------------------------------- | ------ |
| **Locate Upload Interfaces**      | Identify all upload endpoints, including hidden or internal ones | 🔲     |
| **Check for Extension Filtering** | Attempt to upload `.php` and bypass restrictions                 | 🔲     |
| **Test Alternate Upload Points**  | Look for other endpoints (`modify.php`, `edit.php`, etc.)        | 🔲     |
| **Observe File Destination**      | Determine if file is moved to S3 or stored locally               | 🔲     |
| **Attempt Race Condition**        | Re-upload shell multiple times to trigger timing issues          | 🔲     |
| **Check for Error Leakage**       | Look for response anomalies that reveal file paths               | 🔲     |
| **Access File Locally**           | Try accessing leaked local path before transfer completes        | 🔲     |
| **Trigger Reverse Shell**         | Use local file access to execute PHP reverse shell               | 🔲     |
| **Repeat for Reliability**        | Automate or script the race condition for consistent execution   | 🔲     |
| **Confirm S3 Execution Block**    | Ensure shells cannot execute on S3 to avoid false positives      | 🔲     |
