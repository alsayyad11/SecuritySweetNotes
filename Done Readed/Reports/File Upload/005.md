# HackerOne - Unrestricted File Upload via Extension Bypass in Dropcontact

[Original Report](https://hackerone.com/reports/949295)

---

## Overview: What Happened?

A vulnerability in **Dropcontact's file upload functionality** allowed an attacker to upload **HTML files disguised as text files**, leading to a **potential Unrestricted File Upload vulnerability**.

The server failed to properly validate:

* The **file extension** (e.g., `.csv`, `.txt`, `.xls`)
* The **MIME type** of the uploaded file
* The **actual content** of the file

This allowed an attacker to upload files with dangerous content (e.g., HTML + JavaScript) by simply changing their extensions, bypassing front-end restrictions.

---

## Methodology: Step-by-Step Attack Path

### 1. Accessing the Upload Feature

* The attacker created an account on
  `https://app.dropcontact.io/app/`

* Navigated to the upload feature at
  `https://app.dropcontact.io/app/upload/`

---

### 2. Attempt to Upload Restricted File

* Tried uploading a `.html` file
  → Rejected by front-end: only `.csv`, `.txt`, `.xls`, `.xlsx` are allowed.

---

### 3. Bypassing File Type Restriction

* Changed the file extension from `.html` to `.txt`
  → The actual file content remained HTML.

* Uploaded the file again
  → **Upload succeeded** without any server-side validation.

---

## Technical Explanation

The vulnerability stemmed from:

* **Lack of strict validation** on the backend
* Relying only on **file extensions** provided by the client
* No checks on **MIME type** or **file content**
* Front-end enforcement only, which is **easily bypassed**

If an attacker were to discover the upload path or gain access to the uploaded file’s location, this could be used for further exploitation.

---

## Impact

* Potential for **Stored XSS**, **Open Redirects**, or even **Remote Code Execution (RCE)** if the file is executed in a vulnerable context.
* While the file path was not returned to the user, **if leaked or discoverable**, the uploaded file could lead to:

  * **JavaScript execution**
  * **Session hijacking**
  * **Credential theft**
  * **Phishing attacks**

---

## Variants and Extended Scenarios

| Scenario                  | Description                                                                  |
| ------------------------- | ---------------------------------------------------------------------------- |
| **HTML disguised as TXT** | Uploading `.html` files renamed to `.txt`                                    |
| **Client-side bypass**    | Relying only on front-end restrictions without server-side enforcement       |
| **Extension spoofing**    | Using fake or double extensions like `xss.csv.html`                          |
| **MIME-type spoofing**    | Sending `text/html` while pretending to be `text/plain`                      |
| **Blind file execution**  | Uploading malicious file without seeing path, hoping it becomes discoverable |

## Checklist

Use this checklist to test for unrestricted file upload vulnerabilities:

| Step                                | Description                                                | Status |
| ----------------------------------- | ---------------------------------------------------------- | ------ |
| **Upload Feature Found**            | Locate file upload interface                               | 🔲     |
| **Restricted Extensions Confirmed** | Check what extensions are allowed on front-end             | 🔲     |
| **Rename HTML/JS File**             | Change extension to allowed type (e.g., `.txt`)            | 🔲     |
| **Bypass Upload Filter**            | Upload file with dangerous content and allowed extension   | 🔲     |
| **Intercept Request**               | Modify `Content-Type` header and payload in Burp Suite     | 🔲     |
| **Search for File Location**        | Try guessing or discovering the uploaded file path         | 🔲     |
| **Check Execution Context**         | See if file executes when accessed via browser             | 🔲     |
| **Test Polyglot Payloads**          | Files with dual interpretations (e.g., image + HTML)       | 🔲     |
| **Check Response Headers**          | Look for CSP, `Content-Disposition`, MIME-type on download | 🔲     |
| **Double Extension Trick**          | Try uploading files like `xss.csv.html` or `evil.txt.html` | 🔲     |
| **Confirm Backend Validation**      | Ensure server inspects both extension and content type     | 🔲     |
