
# Twitter VPN - Pre-auth RCE via Pulse Secure SSL VPN
[HackerOne Report](https://hackerone.com/reports/591295)

##  Overview: What Happened?

Security researchers from [Devcore](https://devco.re/), led by **Orange Tsai**, discovered that Twitter was using a vulnerable version of **Pulse Secure SSL VPN**, which had multiple critical vulnerabilities allowing for:

- **Pre-auth Arbitrary File Read (CVE-2019-11510)**
- **Post-auth Command Injection (CVE-2019-11542)**
- **Session Hijacking**
- **2FA Bypass via Duo Secret Keys**
- **Ultimately: Full RCE on the VPN Server**

> Even though patches had been released by the vendor in April 2019, Twitter hadn’t applied the update by late May, which left them exposed.

---

##  Methodology: Step-by-Step Attack Path

###  1. Reconnaissance
- Researchers scanned the internet using tools like **Shodan** and **BinaryEdge**.
- Identified multiple unpatched **Pulse Secure VPN** servers in production.
- Verified that Twitter was running a **vulnerable version (< 9.0.4)**.

---

###  2. Exploiting CVE-2019-11510 (Pre-auth File Disclosure)
> No login required — direct file access from internet.

Using this vulnerability, the attacker downloaded sensitive internal files:
```

/etc/passwd
/etc/hosts
/data/runtime/mtmp/system
/data/runtime/mtmp/lmdb/dataa/data.mdb
/data/runtime/mtmp/lmdb/randomVal/data.mdb

```

These files contained:
- VPN usernames and **hashed passwords**
- **Plain-text passwords** (cached by Pulse)
- **2FA credentials** from Duo (Integration key, Secret key, API host)
- **VPN session tokens**

---

###  3. Hijacking Active VPN Sessions
- Extracted session tokens from `data.mdb`
- Reused them to log in directly as VPN users
- No need for username/password if the session was still valid

---

###  4. 2FA Bypass (Duo.com)
- Pulse stored Duo credentials in cleartext in `mtmp/system`
- Retrieved:
  - `integration_key`
  - `secret_key`
  - `api_hostname`
- Allowed attacker to bypass/mimic 2FA process and potentially issue requests as valid users

>  According to Duo documentation: _"Treat your secret key like a password."_

---

###  5. Post-auth RCE via CVE-2019-11542
- Accessed internal admin panel via proxy feature:
```

https\://<target>/admin/

```
- Exploited **Command Injection** on the admin page
- Gained **Remote Code Execution** with full control over the VPN server

---

##  Impact 

-  Internal network access (Intranet)
-  Compromised LDAP credentials and internal servers
-  Dumped plain-text passwords for Twitter staff
-  Could attack all connected VPN clients
-  Recovered private keys and sensitive session cookies (Okta, Salesforce, Box, Google, etc.)
