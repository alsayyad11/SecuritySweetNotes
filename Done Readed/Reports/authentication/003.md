# U.S. Air Force - Authentication Bypass via Response Manipulation

[HackerOne Report](https://hackerone.com/reports/1690548)

---

## Overview: What Happened?

A researcher discovered an **Authentication Bypass vulnerability** affecting a subdomain of the **U.S. Air Force (`*.af.mil`)**.
The vulnerability was found in a login page associated with an internal Harbor registry.

By modifying **server responses** using Burp Suite (changing HTTP `401 Unauthorized` to `200 OK`), the attacker successfully **tricked the client into treating failed login attempts as successful**.

This allowed unauthorized access to **sensitive internal user data** without knowing any valid credentials.

---

## Methodology: Step-by-Step Attack Path

### 1. Reconnaissance

* Targeted `*.af.mil` domains based on scope confirmation.
* Identified a login page at:
  `https://<redacted>/harbor/sign-in`
* The interface appeared to be for admin users or system maintainers.

---

### 2. Initial Login Attempt

* Tried default credentials:
  `admin:admin`
* As expected, received:

```http
HTTP/1.1 401 Unauthorized
```

---

### 3. Intercept & Modify Server Response

> Goal: Trick client into believing the login was successful.

#### Step A: In Burp Suite

* Enable "Intercept response to this request"

#### Step B: Modify response

From:

```http
HTTP/1.1 401 Unauthorized
```

To:

```http
HTTP/1.1 200 OK
```

#### Step C: Forward the edited response

---

### 4. Apply Same Bypass on Other Endpoints

* Targeted sensitive API:

```http
GET /api/v2.0/users/current
```

* Original response:

```http
HTTP/1.1 401 Unauthorized
{
  "errors": [
    {
      "code": "UNAUTHORIZED",
      "message": "UnAuthorize"
    }
  ]
}
```

* Modified response:

```http
HTTP/1.1 200 OK
{
  "message": "Authorized"
}
```

* Repeated this technique across other endpoints and successfully viewed profile data.

---

### 5. Result

* Able to access authenticated user profile information
* No valid session or credentials were required
* Sensitive user data became accessible by tampering with responses alone

---

## Impact

* **Bypassed authentication** without knowing credentials
* **Exposed internal user information** via API calls
* Could escalate further depending on available features (create/edit/delete users, system settings)
* Represents a high-severity issue due to:

  * Lack of proper server-side validation
  * Client-side trust in manipulated responses
