# Snapchat - Improper Authentication via OTP Logout/Login Flow

[HackerOne Report](https://hackerone.com/reports/921780)

---

## Overview: What Happened?

A critical authentication flaw in **Snapchat’s OTP (One Tap Password)** flow allowed an attacker to **log in as any user** by manipulating the `user_id` parameter during the logout step.

The vulnerable endpoint `/scauth/otp/droid/logout` **accepted any arbitrary user\_id**, and in response, returned a valid **OTP token** for that user. This token could then be used to **log in as the victim**, completely bypassing any proper authentication.

> The issue stemmed from **trusting user-controlled input (user\_id)** in a sensitive authentication flow, without proper server-side validation.

---

## Methodology: Step-by-Step Attack Path

### 1. Attacker Logs into Their Own Account

* Attacker performs a normal login to their Snapchat account.
* Establishes a session and captures required headers/tokens.

---

### 2. Abusing the Logout Endpoint

* Sends a **POST** request to `/scauth/otp/droid/logout`.
* **Replaces their own `user_id` with the victim’s `user_id`** in the body.
* Server responds with a **valid OTP token** for the victim!

```http
POST /scauth/otp/droid/logout
Host: gcp.api.snapchat.com

{
  "user_id": "victim_user_id",
  "device_id": "attacker_device_id",
  "device_name": "attacker_device_name"
}
```

➡️ Response:

```json
{
  "status": "SUCCESS",
  "user_id": "victim_user_id",
  "token": "VALID_OTP_TOKEN"
}
```

---

### 3. Logging in as the Victim

* Attacker sends a **POST** request to `/scauth/otp/login`
* Provides the **victim's username** and the **stolen OTP token**
* Server allows login, and attacker gains **full session access as the victim**

---

### 4. Obtaining Victim’s user\_id

* The victim's `user_id` could be obtained via:

  * Sending friend requests
  * Reverse engineering API calls
  * Enumeration from public interactions

---

## Impact

* **Full account takeover** using only the `user_id`
* **No password or OTP verification required**
* Affected any user on the platform
* Exploitable at scale via automation
* Abused Snapchat’s own authentication logic

Snapchat fixed the bug and rewarded the researcher with a **\$25,000 bounty**.

## Checklist

Use this checklist to test for similar Improper Authentication issues:

| Step                       | Description                                               | Status |
| -------------------------- | --------------------------------------------------------- | ------ |
| **Auth Flow Mapping**      | Identify OTP login/logout/auth endpoints                  | 🔲     |
| **Parameter Injection**    | Try replacing user\_id or session-related fields          | 🔲     |
| **Logout Behavior**        | Check if logout accepts arbitrary user\_id                | 🔲     |
| **Token Leakage**          | See if tokens are returned for other users                | 🔲     |
| **Login Attempt**          | Use received token to login as another user               | 🔲     |
| **User ID Enumeration**    | Test how user\_id can be discovered or derived            | 🔲     |
| **Account Takeover Risk**  | Validate if full access is achieved                       | 🔲     |
| **Server-Side Validation** | Check if backend validates that `user_id` matches session | 🔲     |
